## 概念

Volcano 是 K8s 中的容器批量调度平台，基于 kube-batch 演进而来。它提供 gang 调度、公平分配、抢占、拓扑感知等多种能力，特别适合 AI 训练、大数据等需要多 Pod 协同的场景。

核心特性是 **gang 调度**：一组 Pod 要么全部调度成功，要么全部等待。避免了分布式训练中部分 worker 启动、部分卡在 Pending 的尴尬。

## 调度策略

- **Gang Scheduling**：确保作业的所有任务同时启动
- **DRF Scheduling**：多维度资源公平调度，"谁要的资源少，谁的优先级高"
- **Binpack**：尽量把任务塞满节点，提高资源利用率
- **Preemption/Reclaim**：高优先级任务可以抢占/回收低优先级任务的资源
- **Task-topology**：任务拓扑感知调度，优化通信密集型应用性能
- **NUMA Aware**：NUMA 架构感知，优化多核资源分配
- **NodeGroup**：节点分组亲和性调度

> 我用到的是 gang scheduling，保证多个 Job 同时被调度。

## 与 K8s 的交互机制

Volcano **不是替代** kube-scheduler，而是通过 `schedulerName` 字段"认领"特定 Pod。

### 接管 Pod

```yaml
spec:
  schedulerName: volcano  # 声明由 Volcano 调度
```

K8s 允许多调度器共存。Pod 的 `schedulerName` 默认为 `default-scheduler`，设为 `volcano` 后，K8s 内置调度器就不再管它。

### 两条数据流

**读（集群 → Volcano）—— Informer 机制**：

不是轮询，是长连接推送。Volcano 注册了 18 种 Informer（Pod、Node、PodGroup、Queue、PVC、CSI 等），每种绑定 Add/Update/Delete 三个回调。K8s API Server 通过 HTTP Chunked Stream 实时推送变化。

Pod Informer 有额外过滤——只认 `schedulerName=volcano` 的 Pod，其余的丢弃。

**写（Volcano → 集群）—— Binding API**：

调度决策完成后，调用 K8s 标准 Binding API：

```go
db.kubeclient.CoreV1().Pods(p.Namespace).Bind(ctx,
    &v1.Binding{
        Target: v1.ObjectReference{
            Kind: "Node",
            Name: task.NodeName,
        },
    }, metav1.CreateOptions{})
```

随后 Kubelet 看到 Pod 绑定了自己的 Node，启动容器。

### 完整链路

```
Pod 创建(schedulerName=volcano)
      │
K8s 默认调度器 → 跳过
Volcano Informer → 过滤 → AddPod → 进 Cache
      │
runOnce() → Snapshot → Action(enqueue/allocate/preempt) → Plugin(gang/drf)
      │
找到 Node → BindTask() → POST /api/.../binding
      │
Kubelet 启动容器
```

## 调度原理

### Session 快照模式

Volcano 调度不是"来一个 Pod 处理一个"，而是**定时拍快照、统一决策**。

```go
func (pc *Scheduler) runOnce() {
    ssn := framework.OpenSession(pc.cache, plugins, configurations)  // 拍快照
    for _, action := range actions {
        action.Execute(ssn)  // enqueue → allocate → preempt → ...
    }
    framework.CloseSession(ssn)  // 提交结果
}
```

为什么拍快照？一次性读所有 Pod + Node，在内存中规划好，一次性写回，避免中途状态变化导致冲突。

### Action-Plugin 分离

| | Action | Plugin |
|--|--------|--------|
| 职责 | **做什么**（分配、抢占、回收） | **怎么判断**（够不够资源、优先级、gang 约束） |
| 举例 | allocate、preempt、enqueue | gang、drf、priority、binpack |

策略可以自由组合：想去掉抢占就去掉 preempt action，不想用 DRF 就从配置里移除 plugin。

## 结构

- **Scheduler**：核心调度器，通过 Action + Plugin 调度 Job
- **Controller Manager**：管理 CRD 资源生命周期（Queue、PodGroup、VolcanoJob）
- **Admission**：CRD 校验和变更（自动注入 PodGroup 注解）
- **Vcctl**：命令行工具

## 核心概念

- **Queue**：队列，用于资源隔离和优先级排序
- **PodGroup**：一组 Pod 集合，gang 调度的核心
- **VolcanoJob**：扩展 K8s Job，加入 minAvailable、queue、priority

## 使用

```yaml
spec:
  schedulerName: volcano
  annotations:
    scheduling.volcano.sh/group-min-member: "2"
```

关键：`schedulerName: volcano` 才能走 Volcano 调度。查看：`kubectl get pg`
