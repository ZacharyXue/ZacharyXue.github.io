**一句话本质**：`127.0.0.0/8`（IPv6 `::1`）是本机自留地——发给它的包不出物理网卡，在内核协议栈内部直接折返。

## 为什么只能本地通信（机制三层）

1. **路由表拦截**：127/8 是 `local` 表项（dev lo），内核直接吃掉，不上物理网卡
2. **语义自指**：`127.0.0.1` 对每台机器都指「我自己」——跨机器无意义
3. **标准禁止**：路由器不得转发目标为 127/8 的包，它没有「下一跳」概念

## 本地解析流程（connect 127.0.0.1 → 数据回来）

应用 socket → TCP 层 → IP 层查路由表命中 `local`（RTN_LOCAL，不需要下一跳）→ 交给 **lo 逻辑接口**（非物理网卡）→ loopback 发送路径**直接把包塞回本机接收队列**（不碰网卡驱动/线路，不需要 ARP，不封装二层帧）→ IP 剥头 → TCP 处理 → socket 队列 → 应用 recv。

**关键区别**：普通出网 = 内核 → 网卡驱动 → 线路 → 另一端；环回 = 内核 → 直接折返回内核——内核从头干到尾，只是跳过物理世界。实测 ping 127.0.0.1 0.048ms vs 公网 0.927ms，差 20 倍就是证据。

## 实际用途 + 安全

- 本地测试（curl 127.0.0.1）、本机进程间通信、协议栈健康自测
- **bind 127.0.0.1 = 只允许本机访问（安全默认）；bind 0.0.0.0 = 监听所有网卡（暴露风险）**——Redis/MySQL 默认绑 127.0.0.1 即此理；服务被外网连上不该暴露的端口，十有八九是绑了 0.0.0.0

### 为什么外部连不上（绑定地址 = 目标 IP 过滤规则）

```
外部包: 目标 172.19.12.108:9000
  → eth0 收到 → IP 层: 目标 IP 是本机地址 ✅ 收下
  → TCP 层查监听表: 9000 端口的 socket 绑在 127.0.0.1
                   → 只匹配「目标 IP = 127.x」的包
                   → 本包目标 172.19.12.108 ✗ 不匹配
  → 【无 socket 接收】→ 回 RST 拒绝 / 丢弃

本机包: 目标 127.0.0.1:9000 → 匹配 ✅ 连接建立
```

**关键**：端口一直在 `LISTEN`（不是"没打开"），是 socket 的**可达性**限定为「只接受目标是 127.x 的包」。`ss -lntp` 的 Local Address 列就是这个绑定的可视化。
