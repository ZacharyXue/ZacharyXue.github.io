**一句话本质**：`IP/前缀长度`，斜杠后的数字 = 网络号占几位；前缀是"网络有多大"的刻度，剩下的位数才是主机号。

## 核心计算

- 网络地址 = 前 N 位 + 后面全 0
- 广播地址 = 前 N 位 + 后面全 1
- 可用主机 = 2^(32-N) − 2（减网络地址和广播地址）
- 例：`172.16.31.7/20` → 网络 `172.16.16.0`，广播 `172.16.31.255`，可用 4094

## 为什么需要（历史坑）

分类编址（A/B/C 类）只有三档：A 类 1677 万、B 类 6.5 万、C 类 254——**要么不够用，要么浪费一大批**。
CIDR 前缀任意指定：300 台 → /23（510 可用）；只要 2 台 → /30。

## 常用前缀判据

| 场景 | 前缀 | 可用主机 |
|---|---|---|
| 云 VPC 主网段 | /16 | 65534 |
| VPC 子网 | /24 | 254 |
| K8s Pod 网段（Flannel 默认） | /16 | 65534 |
| K8s Service 网段 | /12 | 1048574 |
| 点对点链路 | /30 | 2 |

## 关键事实

- **掩码是 CIDR 的另一种写法**：`/18` ≡ `255.255.192.0`（DHCP 下发用掩码写法，`ip addr` 显示用 CIDR 写法）；掩码决定**直连路由**，进而决定「谁是邻居、谁走网关」
- **前缀决定归属，勿按旧分类脑子想**：`172.16.31.7/20` 在 `172.16.16.0/20`，不在 `172.16.0.0/20`
- **聚合**（=「无类域间路由」的含义）：/25 + /25 → /24，路由表条目变少，避免全球路由表爆炸；VPC 划子网就是用它
- 选多大前缀 = 预期池子里装多少东西（选 /16 就是预留 6 万多个位置）
