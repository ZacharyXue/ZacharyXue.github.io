**一句话本质**：**应用碰不到网卡**——一切联网都要通过**系统调用**把请求交给内核，内核干完活再把结果交还应用；数据在一台机器上要穿越「用户态 → 内核态 → 用户态」。

## 边界图

```
┌──────────── 用户态 ────────────┐
│  应用进程（浏览器 / curl / 你的程序） │
└───────────┬────────────────────┘
            │ 系统调用（唯一的门）
┌───────────▼────────────────────┐
│ 系统调用层: getaddrinfo / socket / connect / send / recv │
│ 协议栈: TCP 分段 → IP 封装 → 路由查表 → ARP │
│ 网卡驱动 + 硬件中断 │
└──────────── 内核态 ────────────┘
```

## 三次穿越

| 穿越 | 系统调用 | 干什么 |
|---|---|---|
| ① | `getaddrinfo()` | 问 DNS：域名对应的 IP 是多少 |
| ② | `socket()` + `connect()` | 创建连接：内核返回 **fd**，三次握手在内核完成 |
| ③ | `send()` / `recv()` | 发数据 / 收数据 |

**socket fd 是什么**：用户态唯一拿到的「会话凭证」——之后 send/recv 都凭它告诉内核「我要跟哪条连接说话」（TCP 端口在编程层的体现）。

## 出方向（发送）

```
应用 send → TCP 分段(加端口) → IP 封装(加地址) → 查路由表 → ARP 查下一跳 MAC → 网卡驱动发出
```
帧结构：`MAC头(源→下一跳) | IP头(源→终点) | TCP头(端口) | 数据`

## 入方向（接收）

```
网卡收到帧 → DMA 到内存 + 硬件中断 → 内核协议栈逐层剥头 → 校验通过 → 放入对应 socket 的接收队列
          → 应用主动 recv() 取走 → 用户态拿到数据
```

> 注意：应用**不是**被中断直接唤醒拿数据——内核把数据放上 socket 队列，应用**主动 recv 取走**。

## 关键认知

- **系统调用是唯一入口**：用户态既看不到协议栈也摸不到网卡，权限边界即安全边界
- **fd 是连接在用户态的代表**：连接状态在内核，用户态只持有编号
- 排障时 `strace -e trace=network` 能直接看到程序发了哪些系统调用（谁在连、连哪、失败在哪一步）

## 排障命令

| 目的 | 命令 |
|---|---|
| 看程序发出的网络系统调用 | `strace -e trace=network <cmd>` |
| 看监听/连接状态 | `ss -lntp` / `ss -ntp` |
| 看 socket 与进程对应 | `ss -lntp`（含 users 列） |
