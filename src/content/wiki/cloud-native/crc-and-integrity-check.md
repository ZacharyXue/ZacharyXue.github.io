**一句话本质**：CRC 用**模 2 除法**给数据算一段"指纹"附在帧尾，链路每跳验证——**查错能力很强（漏检仅 2⁻³²），但因为没有密钥，只能防意外损坏、防不了篡改**。

## 模 2 除法（理解 CRC 的钥匙）

**「模 2」≠ 除以 2**，而是：每位只有 0/1，**超过 1 就绕回来（不进位）** → `1+1=0`。

因此**减法和加法同构 = 异或（XOR）**：

| 运算 | 普通十进制 | 模 2 |
|---|---|---|
| 1+1 | 2（进位） | 0 |
| 1−1 | 0 | 0 |
| **1 XOR 1 = 0，1 XOR 0 = 1** | | |

**算法**：数据后补「多项式位数−1」个 0 → 逐位看最高位，是 1 就拿多项式异或，是 0 就跳过 → 剩下的低位就是余数（CRC）。

```
数据 110101，多项式 1011(x³+x+1)，补 3 个 0 → 110101000
第1步 1101 XOR 1011 = 0110 → 011001000
第2步 1100 XOR 1011 = 0111 → 001111000
第3步 1111 XOR 1011 = 0100 → 000100000
第4步 1000 XOR 1011 = 0011 → 000001100
第5步 最高位 0 → 跳过
第6步 1100 XOR 1011 = 0111 → 000000111
余数 111 → 发送 110101111
接收方对 110101111 再算一遍 → 余数 000 → 无误 ✅
```

**为什么用异或除法**：整套只用异或 → 硬件用移位寄存器几个门电路即可，速度极快（CPU 还有 `crc32_pclmul` 指令级加速）。

## 在网络里的位置

以太网帧**尾部**加 4 字节 **FCS**（Frame Check Sequence）= CRC-32：

```
┌──────┬──────┬──────┬──────┬─────┐
│ MAC头│ IP头 │ TCP头│ 数据 │ FCS │ ← 4 字节 CRC-32
└──────┴──────┴──────┴──────┴─────┘
```

**逐跳检查**：交换机/路由器收到帧先验 CRC，对不上直接丢帧，绝不转发坏数据。

## 检测能力（实测 20000 次随机翻转，漏检 0 次）

| 错误类型 | 能否检出 |
|---|---|
| 单比特错 | ✅ 100% |
| 双比特错 | ✅ 100% |
| 奇数位错 | ✅ 100% |
| 突发错（长度 ≤ 32 位） | ✅ 100% |
| 更长的突发/随机错 | 漏检概率 ≈ 1/2³²（可忽略） |

**不是"只能查一位"**——多位错误照样查得出。

## 能力边界（关键分水岭）

| 能做 | 不能做 |
|---|---|
| 检测损坏 | **不能纠正**（纠正靠重传 = TCP 的活） |
| 硬件级极速 | **不能防篡改**（算法公开、无密钥，攻击者可改数据后重算 CRC） |

**防篡改三分类（本质是"有没有密钥"）**：

| 类别 | 密钥 | 代表 | 防什么 |
|---|---|---|---|
| 错误检测码 | ❌ 无 | CRC-32、TCP 校验和 | 只防意外损坏 |
| 消息认证码 MAC | ✅ 共享密钥 | HMAC-SHA256 | 防篡改 |
| 数字签名 | ✅ 私钥 | RSA / ECDSA | 防篡改 + 防抵赖 |

攻击者改数据后，**无密钥**的校验值可以自己重算 → 验证照样通过；**有密钥**的 HMAC 算不出来 → 篡改暴露。

## CRC vs TCP 校验和（别混淆）

| | 链路层 FCS（CRC-32） | 传输层 TCP checksum |
|---|---|---|
| 位置 | 帧尾 | TCP 头 |
| 范围 | **逐跳**（每段链路各算） | **端到端**（源到目的全程） |
| 强度 | 强（32 位，擅长突发错） | 弱（16 位补码和） |
| 谁验 | 网卡/交换机/路由器 | 目的主机内核 |

两者是**分工不是强弱**：CRC 管"这一跳线路没坏"，TCP 校验和管"端到端全程没坏"（覆盖中间路由器/NAT 的意外改写）。

**HTTPS 的完整性由谁保证**：TCP 之上的 **TLS**——记录层用 HMAC / AEAD（AES-GCM、ChaCha20-Poly1305）带密钥认证。裸 HTTP 时链路 CRC + TCP 校验和都挡不住中间人篡改。

## 运维排查

```bash
ethtool -S eth0 | grep -i crc     # rx_crc_errors 持续增长 = 物理链路故障
                                  # （网线/光模块老化、干扰、接触不良）
```
