**一句话本质**：`IP + 掩码 + 广播地址 + 网关` 是一套团队——**掩码是地基（决定谁是我的邻居），网关是小区唯一大门**；名单错了，你连门都找不到。

## 四件套分工

| 配置 | 回答什么问题 | 缺了会怎样 | 是否需手配 |
|---|---|---|---|
| IP | 我是谁 | 无身份，没法通信 | 需（或 DHCP 给） |
| 掩码（= CIDR） | **谁是邻居**（同子网） | 分不清该直发还是走网关 | 需 |
| 广播地址 | **喊话频道**（ARP / DHCP 广播用） | 找不到邻居的 MAC | **自动算出** |
| 网关 | **出子网的唯一出口** | 只能局域网内通信 | 需 |

## 三个关键认知

1. **掩码和 CIDR 是同一信息的两种写法**：`/18` ≡ `255.255.192.0`。DHCP 下发用掩码写法（`NETMASK=`），`ip addr` 显示用 CIDR 写法（`172.19.12.108/18`）——**不是一个配置，是一个**。
2. **广播地址不用配**：由「IP + 掩码」自动算出（`ip addr` 输出里的 `brd` 就是它）；ARP 请求和 DHCP Discover 都靠它。
3. **硬约束：网关必须落在自己的子网内**——这是掩码正确性的判据。

## 为什么掩码配错就"不通"（核心机制）

**主机判断"谁是邻居"的唯一依据 = 自己的 IP + 自己的掩码**（由此生成直连路由 `172.19.0.0/18 dev eth0 proto kernel`）。

| 配错方向 | 发生什么 | 症状 |
|---|---|---|
| **掩码缩小**（如 /18→/24） | 网关被判为"不在直连网段" → 但远端要靠网关转发，而网关自己不可达 → **死锁** | `Network is unreachable`；包连网卡都出不去 |
| **掩码放大**（如 /24→/16） | 把远端当邻居 → 直接 ARP 一个不在本链路的 MAC → 无人应答 | `Destination Host Unreachable` |

**关键**：不是网关不帮你转，是**你根本走不到网关跟前**——而"走得到"完全由掩码决定。

即使网关恰好落在新范围内（能 ping 通），**邻里地图已经错乱**：原来直连的目标被判为远端要绕网关（多一跳），网关若做反向路径校验（rp_filter）还可能直接丢包。

## 类比

```
掩码 = 你的「邻里名单」
网关 = 「小区唯一大门」

名单错了 → 你以为大门不在自己小区 → 连门都找不到 → 更别提让门帮你送东西
```
