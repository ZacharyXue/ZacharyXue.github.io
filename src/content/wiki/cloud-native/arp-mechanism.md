**一句话本质**：ARP 是**同一条链路上的「IP → MAC 翻译官」**——广播问、单播答、缓存复用；**跨子网时它只问网关**，因为它管不到链路的另一边。

## 为什么需要 ARP

```
三层说: "下一跳是 172.19.63.253"   ← IP, 逻辑地址, 路由器/主机懂
    ↓ ARP 翻译
二层要: "它的 MAC 是多少?"          ← MAC, 物理地址, 网卡才收帧
```

## 工作流程（广播问 + 单播答 + 缓存）

| 步骤 | 动作 |
|---|---|
| ① 查缓存 | 命中 → 直接用缓存的 MAC（不广播，快） |
| ② 未命中 | **广播** ARP 请求：「X.X.X.X 的 MAC 是谁？」目的 MAC = `FF:FF:FF:FF:FF:FF`，同子网所有机器都收到 |
| ③ 应答 | 目标主机**单播**回给自己：「是我，MAC = ...」（不是广播） |
| ④ 写缓存 | 写入 ARP 表，之后一段时间直接用（`REACHABLE` → 久了变 `STALE`） |

## 什么时候问谁（与子网判断挂钩）

| 场景 | ARP 问谁 |
|---|---|
| 同子网（直连） | **目标服务器** |
| 跨子网 / 公网 | **默认网关**（因为二层帧只能送达同一段链路上的设备） |

## 为什么正常 ARP 不会把网络轰垮

| 原因 | 说明 |
|---|---|
| ① 有缓存 → **广播频率极低** | 同一目标几分钟才广播一次，不是每包一次 |
| ② **包极小** | ARP 请求约 28 字节；100 台机器泛洪 ≈ 2.8KB，几毫秒完事 |
| ③ **一次性点射** 而非持续广播 | 主要集中在缓存过期时 |

**注意**：广播帧是「强制到货」——交换机会泛洪到所有端口，每台机器都要看（内核快速比对后丢弃）。「别人不响应」只省了**应答**流量，广播本身照样到达每个人。

## ARP 风暴（把上面三条全打破）

每秒上万次广播请求：
```
10,000 ARP/s × 28 字节 × 泛洪 100 份 ≈ 28 MB/s 纯广播流量
+ 每台机器的 CPU 每秒处理 1 万次广播中断
→ 带宽和 CPU 双杀
```
防御：交换机上的**风暴控制 / ARP 限速**（单位时间广播超限即丢弃）。

## 安全隐患：ARP 无认证

广播问「X.X.X.X 是谁」，**任何机器都可以抢答**——攻击者可伪装成网关，把本该发给网关的流量引到自己这里（**ARP 欺骗 / 中间人**）。缓解手段：交换机端口安全、DHCP snooping、静态 ARP 绑定。

## 排障命令

| 目的 | 命令 |
|---|---|
| 看 ARP 缓存 | `ip neigh`、`arp -a` |
| 看某目标当前走哪 | `ip route get <IP>`（配合判断 ARP 问谁） |
| 抓 ARP 包 | `tcpdump -i eth0 arp` |
