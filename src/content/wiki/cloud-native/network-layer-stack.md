**一句话本质**：HTTP 说"我要买什么"，TCP 说"保证送到并确认"，IP 说"最终去哪个服务器"，MAC 说"当前这一段交给谁"——四层各司其职，每层把上层数据当不可分负载。

## 四层职责

| 层 | 协议 | 管什么 | 类比 |
|---|---|---|---|
| 应用层 | HTTP | 业务数据格式（json 正文/长度/状态） | 快递内容 |
| 传输层 | TCP | ① 端口多路复用（机器上哪个应用）② 可靠传输（ACK/重传/有序拼接） | 收货人 + 签收回执 |
| 网络层 | IP | 端到端地址，全程不变 | 目的地城市+街道 |
| 链路层 | MAC | 逐跳转发，每跳换、不跨网络 | 每一站的车票 |

## 出网链路（浏览器输入域名 → 包出网卡）

1. **应用层**构造 HTTP 请求
2. **DNS**：域名→IP（本机缓存 → /etc/hosts → DNS 服务器递归查询）
3. **TCP 三次握手**（SYN→SYN-ACK→ACK），确定四元组（源IP:源端口 → 目的IP:目的端口）
4. **网络层查路由表**（CIDR 最长前缀匹配）：同子网→直连；否则→默认网关
5. **链路层 ARP**：把下一跳 IP 翻译成 MAC（子网内广播问，目标应答）
6. **封装帧出网卡**，逐跳转发

## 关键事实

- **IP 终点站全程不变；MAC 车票每跳作废**——这是全链路最核心的记忆锚点
- DNS 是应用层翻译器：出现在开头，翻译完使命结束，之后包上只写 IP
- 路由表匹配用「最长前缀优先」（/18 和 /16 同时存在时 /18 先胜出）
- 帧结构：MAC头（源→下一跳）｜IP头（源→终点）｜TCP头（端口）｜HTTP（业务）
