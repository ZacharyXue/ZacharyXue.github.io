## 一句话本质
**用 LLM 做评测不该直接打总分，而应拆成「全局 Rubric 定方向、逐题 Criterion 定检查点」的三层架构**（生成器→打分器→聚合器），并以「打分全程留痕→复盘器定位错因层级→生成候选改法→人工审核」实现自我迭代，用训练/测试集分工防退化——底层哲学是**让 LLM 把 bad case 变成具体改法，而不是让它自己宣布「我变好了」**。

## 关键认知：Judge 是代理指标

LLM-as-Judge 测的是"看起来好不好"，**不等于"业务上有没有用"**。这个 gap 是所有评测问题的总根源——Judge 的打分必须被实验层校准（见 [Agent 评测体系](/wiki/llm-eng/agent-eval-framework)），不能自己说了算。裸打分的三个系统性陷阱（位置偏差 / 选择过拟合 / 一致性 ≠ 正确性）与 Rubric 化解法见 [Rubric 化评估器](/wiki/llm-eng/rubric-based-judge)。

## 反模式（为什么不能直接打总分）

给 LLM 一个问答让它打 1-5 总分有两大死穴：①分数说不出原因（3 分和 4 分差在哪无法解释）；②无法迭代改进（不知道错在哪个环节就不知道该改什么）。

## 三层架构（可定位错因）

| 层 | 职责 | 关键约束 |
|---|---|---|
| 检查项生成器 | 输入问题+FAQ+上下文+rubric，产出正向/负向 criterion 清单 | **生成时不能看被测答案**，防「看答案编标准」 |
| 检查项打分器 | 不做综合评价，逐条判断覆盖/踩雷/证据句 | 每条检查项独立判断 |
| 规则聚合器 | 纯规则不调 LLM，输出总分+风险级 | 确定性聚合 |

**错因映射**：坏答案被放过→生成器漏了风险点；好答案被误杀→criterion 写太死；分怪→聚合规则太狠。

## 自我迭代闭环（前提是过程留痕）

- **留痕**：每次打分记录生成了哪些检查项、每条是否通过、证据是哪句、为什么给这个分——没有过程只有分数，迭代就没有入口。
- **复盘器三步**：Step1 挑可疑样本（bad case）→ Step2 定位错因层级（现象对应哪层根因，针对性修改）→ Step3 生成候选修改（具体改动+为什么改+预期修什么+影响哪些旧样本）。人的角色从「判卷」变成「审核改法」。
- **防退化（ML 朴素分工）**：训练集暴露 bad case 可反复调；测试集固定不动专做验收（训练集提升不算数，测试集表现才是真指标）。测试集保留两类样本：稳定样本（防误杀好答案）+ 困难样本（防同类错误反复出现）。每轮迭代做版本快照（数据批次/模块版本/模型/修好哪些 bad case/测试集表现）。

## 方法论迁移：代码评审

检查项生成器=按 PR 类型（策略回测/数据管道/配置修改）生成评审清单；打分器=拿 checklist 逐条对照；复盘器=线上出 bug 回头分析评审为什么没抓到，自动生成新检查项；训练/测试集=带已知 bug 的历史 PR 样本库 + 固定测试集。

## 人的位置
人没有被拿掉，只是从重复判断变成做更重要的决策——哪些标准不能变、哪些边界不能越（**校准尺子，而不是被 LLM 替代**）。

## 记住点
让 LLM 把 bad case 变成具体的改法，而不是让它自己宣布「我变好了」——人从判卷者变成校准尺子。
