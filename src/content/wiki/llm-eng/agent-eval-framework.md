## 一句话本质
**评测体系要回答三个不同问题——「评什么」（五层评测对象）「评完怎么办」（四步质量归因）「怎么上线」（三阶段治理）；判据方法分规则/模型/实验三层且互相校准（实验层校准模型层，模型层放大规则层），最容易被忽略的是级联风险：下层不干净，上层白评。**

## 与单个评估器的关系

单个评估器（见 [Rubric 化评估器](/wiki/llm-eng/rubric-based-judge)）解决"这一把尺子准不准"；体系解决"用哪些尺子量什么、量完干什么、什么时候能放行"。

## 五层评测对象（评什么）

| 层 | 评什么 | 判据 | 失败的含义 |
|---|--------|------|-----------|
| L1 Prompt 约束 | 规则遵循、格式、安全边界 | 硬规则 | 连规则都遵守不了，不能进入效果讨论 |
| L2 知识与经验 | 历史策略理解、经验复用 | 规则 + Judge | 知识不可靠，后面全白搭 |
| L3 任务执行 | 工具调用、参数正确性、链路完整 | 规则为主 | 工具/参数/链路问题 |
| L4 业务效果 | 与 ROI/GMV/损益的匹配度 | Judge + 实验 + 归因 | 业务视角不成立 |
| L5 自动化 Benchmark | 长期回归、跨版本对比 | 基准集 | 无法判断版本进退步 |

⚠️ **级联风险**：L1~L3 不干净，L4 的"业务效果"判断会被污染——先清下层，再谈效果。

## 评测方法三层（互相校准）

| 层 | 方法 | 特点 | 主要适用 |
|----|------|------|---------|
| 规则层 | 硬规则、格式校验 | 确定、便宜、覆盖窄 | L1 / L3 |
| 模型层 | LLM-as-Judge | 覆盖广、需校准 | L2 / L4 |
| 实验层 | A/B 实验 + 后置归因 | 最接近真实业务、最贵、周期长 | L4 |

**不是替代关系**：实验层校准模型层（防止 Judge 自我确信），模型层放大规则层（扩大覆盖面）。

## 四步质量归因（评完怎么办）

1. **分层诊断**——先判断问题落在哪一层
2. **根因定位**——定位到具体模块/环节
3. **路由优化**——按根因类型分派到对应优化动作
4. **回归验证**——改动后回跑，确认修复且无新增退化

## 三阶段上线治理（怎么上线）

| 阶段 | 目标 |
|------|------|
| 准入 | 达标才能上线（质量门禁） |
| 灰度 | 小流量验证真实业务效果 |
| 监控 | 持续观测，异常可回滚 |

## 评测数据集设计

三批：**基础能力验证 / 边界与风险探测 / 评估器能力验证**——第三批最容易漏，即"评估器本身也要被评估"。

## 记住点

五层定"评什么"、四步管"评完怎么办"、三阶段管"怎么上线"；而整条链的胜负手是——**先把裁判评明白，再去评 Agent**（未经校准的 Judge 带来的虚假信心，比没有 Judge 更危险）。
