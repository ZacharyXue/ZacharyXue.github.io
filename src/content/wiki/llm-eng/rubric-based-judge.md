## 一句话本质
**LLM-as-Judge 只是「代理指标」（测看起来好不好，不等于业务有没有用），裸打分必踩三个系统性陷阱；Rubric 化的解法是「判据人写 + 逐条判定 + 统计纪律（Bootstrap 稳定性筛选 / 交叉验证贪心）+ 换锚校准（人工与业务）」——目标是高精度优于高覆盖。**

## 为什么需要 Judge

传统测试在被评对象是自由文本时失灵：字符串匹配/断言写不出来。人工评估贵、慢、不可复现、会疲劳。Judge 便宜、快、可批量、可复跑。

| 形态 | 做法 | 可靠性 |
|------|------|--------|
| 直接打分 | "打几分？" | 较差（绝对分数没标尺） |
| 成对比较 | "A 和 B 哪个好？" | 较好（比较比绝对打分容易） |

## 关键认知：它是代理指标

Judge 测的是"看起来好不好"，不是"业务上有没有用"。这个 gap 导致「离线合理 ≠ 业务有效」，所以 Judge 的打分必须被**实验层校准**，不能自己说了算。

## 裸 Judge 的三个系统性陷阱

「系统性」= 会稳定地骗你，不是偶发错误。

| 陷阱 | 表现 | 根因 |
|------|------|------|
| 位置偏差 | 同一对回答交换顺序后结论翻转（实测一致性 96% → 50%） | 模型偏好"先看到的"；**比较题给了位置发挥空间** |
| 选择过拟合 | 挑出的准则在当前样本好，换批数据就崩 | 在有限样本上反复挑 = 噪声被当信号 |
| 一致性 ≠ 正确性 | 多个 Judge 高度一致，但一起错（偏爱长回答/被骗过/漏事实错误） | 偏好与人类业务判断不一致；同源模型有共同偏差 |

裸 Judge 的致命处不是会错，而是**错得看不见、说不出、修不了**。

## Rubric 是什么

把模糊的「好」拆成一组具体、可判定的准则；每条准则是一道**判断题**（满足/不满足），不是感觉题。

| 准则 | 判定标准 | 类型 |
|------|---------|------|
| 依据可追溯 | 结论都能指向输入里的具体数据 | 必要条件 |
| 约束遵守 | 不超预算上限 | 一票否决 |
| 逻辑自洽 | 前提→推理→结论无跳步 | 计分项 |

### ⚠️ 最易搞错的一点

Rubric **不是**把 LLM 换成代码规则——如果规则能判，就不需要 Judge（那是规则层的事）。**判据依然由 LLM 判**，变的是**问法**：从"整体感觉打几分"变成"逐条准则是否满足"，输出空间被压缩，因此可解释。

## Rubric 如何针对性治三病

| 陷阱 | 解法 |
|------|------|
| 位置偏差 | **把比较题变成判断题**：不问"A 和 B 谁好"，而问"是否满足准则 X"——判断题无 AB 顺序，位置偏差失去作用点 |
| 选择过拟合 | **稳定性筛选**：多次重采样只留"换个样本还在"的准则；再用**交叉验证 + 贪心组合**验证整体 |
| 一致性 ≠ 正确性 | **换锚点**：不拿"模型之间是否一致"当标准，而拿人工/业务专家判断当锚，最终锚是真实业务结果 |

## 三层筛选机制（准则本身也要被验证）

| 层 | 解决的问题 | 手段 |
|----|-----------|------|
| 一 | 方向对不对、判断稳不稳、能否泛化 | 双侧验证 / 位置交换一致性 / 稳定性筛选 + 交叉验证贪心 |
| 二 | 结论在没见过的数据上可信吗 | 独立样本验证 |
| 三 | 能否当金标准 | 多轮独立评估一致且方向正确 → 纳入 Golden Set |

**稳定性筛选的具体做法**：Bootstrap 重采样 200 轮，每轮抽 70% 偏好对，在子样本上独立跑贪心准则选择，统计每条准则的**被选中频率**，按频率排序取 Top-K 作候选池——高频入选 = 真规律，偶然入选 = 在拟合噪声。

**交叉验证贪心**（防"既选又评"的乐观偏差）：从空集开始，每步尝试加入一条剩余准则，只在**验证集**上评估准确率变化，有提升保留、无提升跳过，直到无法继续。

## 与传统 Reward Model 的取舍

| 维度 | 传统 Reward Model | Rubric 化 |
|------|------------------|-----------|
| 可解释性 | 一个分数 | 每条准则可对照 |
| 数据需求 | 大量偏好标注 | 小样本 + 统计纪律 |
| 迭代速度 | 需重训 | 改准则即可 |
| 调试能力 | 黑箱 | 定位到具体准则 |

## Rubric 优化了 Judge 的四件事

| 手段（机制层） | 结果（能拿它干什么） |
|---------------|-------------------|
| 判据人写 + 逐条判定 | **① 可解释**：错在哪一条，直接指回 Prompt |
| 交换检验 + Bootstrap | **② 可复跑**：不稳的准则被剔除，接近幂等 |
| 准则集封闭、自由度压缩 | **③ 可交付**：能当准入/回归的质量门禁 |
| 从业务目标反推准则 | **④ 对齐**：评业务在乎的事，不是"看起来好" |

⚠️ 措辞精确性：是「**接近**幂等」不是真幂等——LLM 是概率系统，同判据下仍有波动。工程目标不是幂等，而是「**噪声可量化 + 误差可接受**」。裸 Judge 的问题是你不知道它稳不稳；Rubric 让你能说出"这条准则位置一致性 96%、那条只有 50%"，从而剔除不稳的。

## 记住点

不是让裁判变聪明，而是让裁判**可解释、可复跑、可交付，并盯住业务真正在乎的东西**——「能用确定性代码写的绝不交给模型；模型必须上的地方，用脚手架把自由度框死」。

## 自测

1. 为什么"用 LLM 打分"不能直接上，要先写 Rubric？（从位置偏差 + 可解释性各说一句）
2. Rubric 里的判定是谁在做？如果换成代码规则会失去什么？
3. Bootstrap 200 次 × 70% 抽样统计"选中频率"，解决的是哪个陷阱？为什么"频率"能区分信号与噪声？
